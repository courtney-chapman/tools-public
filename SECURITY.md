# Security Policy

## Supported source

Only the current `main` branch is maintained. Published or installed copies
should be compared with the current repository source before reporting a
problem.

## Reporting a vulnerability

Do not open a public issue containing credentials, private data, exploit
details, or sensitive procurement information. Use GitHub's private
vulnerability-reporting channel when available, or contact the repository owner
privately through GitHub.

Include the affected plugin, relevant file or version, observed behavior, and a
minimal disclosure-safe reproduction. Do not attach real case files, source
selection information, controlled data, credentials, or personal information.
