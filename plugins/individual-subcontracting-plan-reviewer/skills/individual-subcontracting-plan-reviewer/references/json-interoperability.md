# Plan Builder JSON interoperability

The published Individual Subcontracting Plan Builder exports `schemaVersion: "1.0"` and `planType: "individual"`. Read the supplied object, not a presumed future schema. Relevant top-level keys are `contractor`, `contract`, `periods`, `opportunities`, `goalMethodology`, `sourceIdentification`, `sourceOther`, `proposalBusinesses`, `indirectCosts`, `administrator`, `equitableOpportunityMeasures`, `measureOther`, `assurances`, `recordsMaintenance`, `submission`, and `buyerNotes`.

Each `periods[]` row has a stable `id`, `name`, `contractValue`, `direct`, `indirect`, and `zeroExplanations`. Category keys in `direct` and `indirect` are `lb`, `sb`, `sdb`, `wosb`, `hubzone`, `vosb`, and `sdvosb`; amounts are strings. An empty string means unknown; `"0"` is an entered zero. `indirectCosts.status` is `yes`, `no`, or `unknown`. Opportunity rows have `id`, `description`, `amount`, `categories`, and `notes`. Do not infer supplier awards from these projected rows.

`contract.basis`, `contract.alternate`, `contract.dfars`, and `contract.clauseDate` record the user's governing-text selections; they do **not** prove clause incorporation. `contract.contractPct` records whether the user marked contract-dollar percentages as required. `assurances.overrides` contains the user's chosen departures from the builder's default text; preserve them and review against the actual clause. `submission.approvalRecorded` and related fields are user entries, not verified Government approval.

For a read-only review, do not rewrite JSON. Cite paths and period IDs in findings where useful. If asked for updated JSON, start from the supplied object and preserve all keys, extension fields, row IDs/order, numeric strings, classifications, narratives, and approval fields except changes the user explicitly requests. Provide a change log. Do not silently migrate schema versions, insert invented values, or stuff findings into unsupported fields. If the requested correction cannot safely be represented in the supplied schema, return the original unchanged and give the proposed change separately or request the target mapping.
